# Contributing

Thanks for contributing to `kraken-sockets`.

## Code of Conduct

Contributors are expected to be respectful, constructive, and focused on improving the project. Harassment, personal attacks, and disruptive behavior are not acceptable.

## Development Workflow

1. Fork the repository and create a feature branch from `main`.
2. Make focused changes with clear commit messages.
3. Run the test suite with `go test ./...`.
4. Update documentation when behavior, deployment, or operational details change.
5. Open a pull request with a clear summary of the problem, solution, and any rollout considerations.

## Pull Request Guidelines

- Keep pull requests narrowly scoped.
- Include tests when changing behavior.
- Document any configuration, deployment, or protocol changes.
- Call out breaking changes explicitly.

## Reporting Issues

When opening an issue, include:

- A clear description of the problem
- Steps to reproduce
- Expected behavior
- Actual behavior
- Relevant logs, screenshots, or packet samples when applicable

## Review Expectations

Pull requests may be asked to address correctness, test coverage, operational safety, or maintainability concerns before merging.
